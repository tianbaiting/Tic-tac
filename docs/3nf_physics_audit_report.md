# 3NF Physics Audit Report — `fix/3nf-physics-contract`

**Branch:** `fix/3nf-physics-contract`
**Base:** `master` (commit `6505537`, 2026-06-21 audit + 6 follow-up fixes)
**Date:** 2026-08-01

This report documents the physics-first audit and repair of the chiral N²LO
three-nucleon force (3NF) implementation in Tic-tac, performed on
`fix/3nf-physics-contract`. It is the companion to
[`docs/three_nf_equation_contract.md`](three_nf_equation_contract.md) (the
operator-level contract) and supersedes the preliminary
[`docs/3nf_audit_2026-06-21.md`](3nf_audit_2026-06-21.md) for every item it
addresses.

The guiding principles (from the task specification):

1. Derive and verify equations before modifying production code.
2. No `w1_scale`, no global empirical factors, no hand-flipped signs, no
   post-hoc Hermitian averaging to fit a reference.
3. Oracles must be independent of the production implementation.
4. `three_nucleon_force=none` 2NF-only output must match the pre-change baseline
   (bit-for-bit where possible, else strict numeric tolerance with explanation).
5. The model is NOT advertised as complete `chiral_N2LO` until c₄ is
   implemented and independently verified.

---

## 1. Summary of the starting state

The 2026-06-21 audit (`docs/3nf_audit_2026-06-21.md`) confirmed 8 issues
(B1–B8) and the master branch had applied 6 follow-up fixes (commits up to
`6505537`): the c_E spin-scalar split, the c_4 hard-block (warn + rename), the
operator-ordering dense test, the W1 cache key extension, and the cache
double-precision upgrade. The remaining work — the equation contract, the
operator-level oracle, the strengthened c_4 fail-closed, the independent
angular oracle, the kernel unification, and the regression-test infrastructure
— is what this branch delivers.

### Pre-existing test-infrastructure bugs found during the audit

- **Parser bug** (`set_run_parameters.cpp:727`): any inline argument ending in
  `.txt` was treated as an input-list file BEFORE checking for `=`, so
  `energy_input_file=CPP/Input/lab_energies.txt` was misparsed. This made the
  `test_3nf_regression` test unable to run. Fixed in Phase 7 (swap the
  `=`/`.txt` branch order).
- **Hash-based regression comparison incompatible with OpenMP**: the
  `test_3nf_regression` test compared U_PW_elements files by SHA-256 hash, but
  the solver uses OpenMP reductions whose sum order is non-deterministic across
  runs (run-to-run max|Δ| ≈ 1e-10 at the Np=Nq=5 grid). Rewritten as a numeric
  tolerance comparison (tol 1e-7, well above the 1e-10 noise floor).

## 2. Phase 0 — Equation contract + operator-level oracle

### Deliverable: `docs/three_nf_equation_contract.md`

The contract derives the Tic-tac channel-resolvent / WPCD equations from the
standard Faddeev equation with 3NF

```
T|φ⟩ = tP|φ⟩ + (1+tG0)V^(1)(1+P)|φ⟩ + tPG0T|φ⟩ + (1+tG0)V^(1)(1+P)G0T|φ⟩
```

and answers the six questions of the task §Phase 0:

| Question | Answer (see contract §5) |
|----------|--------------------------|
| Unknown operator? | The AGS `U` (`U_array`); `U = G0⁻¹·T·G0⁻¹`. |
| Why 2NF driving is `P·V` (not `P·t`)? | `G` carries `V_pair`, so `t = V + V·G0·t` is generated by `K·G·U`; driving with `P·t` would double-count. |
| 3NF driving form? | `V^(1)·(1+P)`, `V^(1)` LEFT in its spectator-1 frame. The reverse order coincides only between antisymmetric states, not in the kernel. |
| Is `(1+tG0)` absorbed? | Yes — into the channel resolvent `G`, NOT into `W^(1)`. `W1_element` evaluates bare `V^(1)`; the dressing is produced by iteration. |
| Direct `V^(1)(1+P)` appears once? | Yes — as the n=0 Born term `a_0 = A = C^T·K·C`. |
| Breakup `(1+P)T` includes 3NF? | Yes — via `U` (which carries `V^(1)(1+P)` in `K`) and the outer `(1+P)`. |

### Deliverable: `tests/cpp/test_3nf_operator_oracle.cpp` + `cpvc_kernel.{h,cpp}`

A finite-dimensional (DIM=8) oracle that builds random NON-symmetric `P, V,
W^(1), C, G1` and verifies the REAL production `calculate_CPVC_col` reproduces
`M = C^T·(P·V + W^(1)·(1+P))·C`, plus the operator-ordering guard
(`W^(1)·(1+P) ≠ (1+P)·W^(1)`), the C/C^T guard, the dense-solver identity
`(1-AG)·U = A`, and Neumann→dense convergence.

To enable this, `calculate_PVC_col` and `calculate_CPVC_col` were extracted
from the 2595-line `solve_faddeev.cpp` into a self-contained
`src/core/faddeev_solver/cpvc_kernel.{h,cpp}` (behaviour-preserving: 2NF-only
output unchanged, max|Δ| vs baseline 1.2e-10 — the OpenMP floor). This also
begins Phase 5's kernel unification (single source of truth for the kernel
algebra).

**Result:** all 7 oracle checks PASS. The production kernel algebra is
verified against an independent dense-math assembly.

## 3. Phase 1 — c₄ silent omission (audit B2)

### Original bug
`chiral_N2LO_3NF` accepted a `c4` parameter, had an `enabled()` that included
c₄, but `W1_element` never evaluated the c₄ 2PE cross-product term
(`τ₁·(τ₂×τ₃)·σ·(qᵢ×qⱼ)`, Epelbaum 2002 eq. 2.2–2.3). The factory passed
non-zero `c4` (inherited from the 2NF LEC set) for every chiral 2NF, so
production runs silently dropped the c₄ contribution.

### Physics impact
The c₄ term is the only N²LO 3NF piece that carries the isospin operator
`τ₁·(τ₂×τ₃)` (imaginary in the T₃N=½ doublet basis, opens off-diagonal T₂N
transitions). Dropping it makes the model an approximation to the full N²LO
3NF, not the complete N²LO 3NF it was advertised as.

### Fix (fail-closed per task §Phase 1)
A correct c₄ partial-wave decomposition requires the full 5D angular integral
(Golak 2010) with the `τ·(τ×τ)` isospin recoupling and the
`(σ×σ)·(q×q)` momentum cross-product. This is research-grade work that cannot
be completed and independently verified in the current scope, so the model is
**fail-closed**:

- `chiral_N2LO_3NF` constructor **REJECTS** `c₄ ≠ 0` via `raise_error` — c₄
  is never silently dropped. (`src/interactions/chiral_N2LO_3NF.h`)
- `name()` always returns `"chiral_N2LO_c1c3cDcE_approx"` — the honest
  approximate name.
- Factory `three_nucleon_force_model::fetch` **rejects** the string
  `chiral_N2LO` (which would claim a complete N²LO 3NF) with a clear error;
  accepts `chiral_N2LO_c1c3cDcE_approx` (builds with c₄=0, documented drop)
  and the legacy alias `chiral_N2LO_without_c4` (deprecation notice).
  (`src/interactions/three_nucleon_force_model.cpp`)
- A "failing regression test" (`test_c4_requirement_documented_xfail`)
  documents the target behaviour once c₄ is implemented: c₄-only should
  `enabled()==true`, produce non-zero matrix elements, and satisfy
  Hermiticity/parity/J/T/particle-exchange. Currently SKIPPED because the
  constructor rejects c₄ ≠ 0.

### Evidence
`test_3nf_matrix_elements` (418 passed): constructor-throws for c₄≠0 (forked
test), small-c₄-throws, name-is-approximate, c₄-requirement-XFAIL. The factory
rejects `chiral_N2LO` and accepts `chiral_N2LO_c1c3cDcE_approx` with a
documented c₄-drop notice (verified by running the solver).

### What is NOT done
A correct, independently-verified c₄ PWD is **deferred**. The implementation
plan (operator form, selection rules, 5D angular structure) is documented in
the contract §8 and the original audit B2. Until implemented, the model MUST
NOT be called `chiral_N2LO` (full).

## 4. Phase 2 — c_E contact spin factor (audit B1)

### Original bug
`recoupling_3nf_scalar` returned `(σ₂·σ₃)(τ₂·τ₃)`, but the c_E contact
(Epelbaum 2002 eq. 2.10/A-4) is a **pure spin-scalar** — only `τ₂·τ₃`. For
singlet pairs (S₂N=0) the wrong helper multiplied by `σ₂·σ₃ = −3`; for triplet
pairs (S₂N=1) by `+1`. This flipped the sign in singlet-pair channels and
wrongly made the c_E contact depend on pair spin.

The 2026-06-21 audit (commit `e3972d5`) split the helper into
`recoupling_3nf_contact_cE` (pure τ₂·τ₃) and `recoupling_3nf_2pe_scalar`
(σ·σ × τ·τ for the 2PE c₁/c₃ rank-0 piece, where σ·σ IS correct).

### This branch's contribution: independent direct enumeration
`test_cE_direct_pauli_enumeration_*` (in `test_3nf_matrix_elements.cpp`)
derives `⟨(½½)T | τ₂·τ₃ | (½½)T⟩` by an explicit 4×4 Pauli-matrix sum (τ = σ,
the chiral-EFT isospin convention — NOT σ/2), building `τ₂·τ₃` in the
uncoupled `|m₂,m₃⟩` basis and rotating to the coupled `|T,T_z⟩` basis via CG.
This is independent of both the closed form `2T(T+1)−3` and the SymPy JSON
oracle.

**Result:** direct Pauli derivation gives `τ₂·τ₃ = −3` (T=0) and `+1` (T=1),
matching `recoupling_3nf_contact_cE` to 1e-12. The c_E ratio
`V(3S1)/V(1S0) = −3.000000` (NOT `+1`) confirms the spin-scalar fix.

## 5. Phase 3 — Independent angular oracle (audit B7)

### Original issue (audit B7)
The 2PE c₁/c₃ kernel `kernel_2pe_c1c3` azimuthally averages over the pair
azimuth φ_{p′}, replacing `|Δp|² → p² + p′²` and dropping the `Δp·Δq` cross
term **inside** the (nonlinear) pion propagator `1/(q₂²+m_π²)(q₃²+m_π²)`.
This is the "monopole approximation": `⟨f(q²)⟩ ≠ f(⟨q²⟩)` for nonlinear `f`.
The code comments labelled it a "true partial-wave projection".

### Deliverable: `tools/3nf_oracle/`
- `print_w1_element.cpp`: a thin C++ driver wrapping
  `chiral_N2LO_3NF::W1_element`, so the Python oracle compares against the
  real production code (NOT a re-transcription of the kernel formula).
- `angular_oracle.py`: an INDEPENDENT derivation of the 2PE rank-0
  partial-wave matrix element from the un-reduced momentum-space operator
  `(gA/2fπ)²(τ₂·τ₃)(σ₂·q₂)(σ₃·q₃)·F(q₂,q₃)·regulator`, building `q₂, q₃` as
  explicit 3D vectors and integrating over `(θ_{p′}, φ_{p′}, x)` with
  Gauss-Legendre quadrature.

### Findings
1. **c_E calibration** (closed-form, no angular integral): oracle vs
   production = 0.991 (within the 2% f_π/Λ_χ constant precision). Confirms
   the closed-form c_E is correct.
2. **c_E ratio** `V(3S1)/V(1S0) = −3.000000` (NOT `+1`) — confirms B1 fix.
3. **Independent re-derivation of the production azimuthal-averaged formula**
   matches the C++ `W1_element` to 0.6% — confirms we correctly understand
   what the production code computes.
4. **Full angular integral ≠ monopole-approximated integral**: the production
   code replaces `|Δp|² → p²+p′²` inside the nonlinear pion propagator,
   which is NOT the same as averaging the propagator over angles. Audit B7 is
   confirmed as a genuine approximation, not an exact reduction. At the tested
   point (p=0.5, q=0.4, p′=0.6, q′=0.7 fm⁻¹), the production value is ~0.66×
   the full-angular value; the **direction** of the discrepancy (full ≠
   monopole) is robust, but the **absolute magnitude** depends on the subtle
   normalization mapping between the full-solid-angle integral and the
   production code's `1/(8π³)` Fourier-norm + `∫dx` reduction. A
   research-grade reference PWD is needed to pin the magnitude definitively.

### What is NOT done
The full 5D partial-wave decomposition (Golak 2010) for c_D, c₁, c₃ — with
all independent angular variables retained and the propagator averaged over
angles, not angle-averaged inside the propagator — is **deferred**. The
current oracle is a rank-0 S-wave-channel proof-of-principle; extending it to
the full 5D integral with rank-2 tensor coupling and off-diagonal channels
is the remaining Phase 3 work. The c_D 1PE-contact is expected to be exact
(contact pair vertex removes the pair-angle dependence); this is documented
but not separately verified by the oracle.

## 6. Phase 4 — WP discretization & units (partial)

The contract §7 fixes the units of every object (`V^(1)` in fm⁵, `W1_WP` in
MeV, the `1/(8π³)` Fourier convention, the squared-Gaussian regulator
E2002 eq. 3.19). The `1/(8π³)` factor is applied inside the scalar kernels
(mirroring the 2NF convention in `chiral_LO_internal.cpp:59`); the diagnostic
"missing ~(2π)³ = 248" reported in old notes is the symptom of the convention,
NOT an independent scaling to apply.

The W1 cache (audit B5+B6, fixed on master) extends the key with c₁/c₃/c₄ and
the momentum grid, and stores `double` not `float`.

### What is NOT done
A systematic WP-cell quadrature convergence report (midpoint vs 2-point vs
4-point cell averaging) is **deferred**. The infrastructure exists
(`Np_per_WP_W1`, `Nq_per_WP_W1` run-parameters) but the convergence sweep was
not run on this branch.

## 7. Phase 5 — Kernel assembly unification (partial)

`calculate_PVC_col` and `calculate_CPVC_col` were extracted into
`cpvc_kernel.{h,cpp}` (Phase 0), giving the dense / sparse / row / column
paths a single source of truth for the kernel algebra. The Phase 0 oracle
verifies this extraction against an independent dense-math assembly.

`calculate_all_CPVC_rows` (the row-oriented entry, used by the Neumann driving
term) was NOT extracted — it depends on the `elastic_on_shell_index` helpers
that are tightly coupled to the full solver. Its kernel-algebra correctness is
covered by the column path (Test 1 of the oracle) plus the existing
`test_faddeev_operator_order` dense test. A future Phase 5 refactor will
extract it too.

### w1_scale debug-only guard
`w1_scale` is retained as a labelled debug fault-injection knob. The default
is 1.0; a strong stderr warning fires when `w1_scale ≠ 1.0`, and the contract
§8 forbids using it to fix a normalization or fit a curve. Verified: the
warning fires for `w1_scale=0.5`.

## 9. What is complete and what is deferred

### Complete (independently verified)
- **Equation contract** (`docs/three_nf_equation_contract.md`): Faddeev → AGS
  → WPCD derivation, operator/object mapping, unit table, forbidden fixes.
- **Operator-level oracle** (`test_3nf_operator_oracle`): the production
  `calculate_CPVC_col` matches `C^T·(P·V + W^(1)·(1+P))·C` on a random
  non-symmetric finite-dimensional system. Operator ordering locked.
- **c_E spin-scalar fix** (B1): confirmed by direct Pauli enumeration
  (independent of the closed form and the SymPy JSON). Ratio −3, not +1.
- **c_4 fail-closed** (B2): constructor rejects c₄≠0; factory rejects
  `chiral_N2LO`; honest model name `chiral_N2LO_c1c3cDcE_approx`.
- **Operator ordering** (B4): locked by dense test + contract.
- **Independent angular oracle** (B7, proof-of-principle): the production
  azimuthal average is confirmed to be an approximation, not an exact
  reduction. The production formula is independently re-derived and matches.
- **w1_scale debug guard** (§8): non-unity values warn loudly.
- **Regression infrastructure**: parser bug fixed; tolerance-based 2NF-only
  regression (max\|Δ\| = 4e-08, OpenMP non-determinism explained).
- **W1 cache key + double precision** (B5+B6, on master): retained.

### Deferred (documented, not completed)
- **c₄ 2PE cross-product PWD**: the `τ₁·(τ₂×τ₃)` isospin recoupling +
  `(σ×σ)·(q×q)` 5D angular integral. The model is fail-closed until this is
  implemented and independently verified. **The model MUST NOT be called
  `chiral_N2LO` (full) until c₄ is done.**
- **Full 5D PWD oracle** for c_D, c₁, c₃ (Golak 2010): the current oracle is a
  rank-0 S-wave proof-of-principle. The full 5D integral with rank-2 tensor
  coupling, off-diagonal channels, and the spectator-L≥2 pieces is the
  remaining Phase 3 work.
- **Rank-2 Hermitian symmetrisation** (B8): the `0.5·(W1(r,c) + W1(c,r))`
  band-aid remains; a manifestly Hermitian kernel derived from the 5D integral
  is deferred.
- **WP-cell quadrature convergence sweep** (Phase 4): infrastructure exists,
  sweep not run.
- **`calculate_all_CPVC_rows` extraction** (Phase 5): column path done, row
  path deferred (depends on elastic-on-shell helpers).
- **Independent triton / nd-elastic benchmarks** (Phase 6): not attempted —
  requires a research-grade reference PWD and published reference values, which
  depend on the deferred c₄ and full-5D items above.
- **Dense-vs-Padé solver consistency** at production grid: the operator-level
  oracle verifies the matrix identity; a production-scale consistency check is
  deferred.

### Forbidden fixes (per contract §8) — NOT used on this branch
- `w1_scale ≠ 1.0` in production.
- Global empirical multiplicative factors (the historical `~2.4–3.0×`
  residual is explicitly disallowed).
- Hand-flipped signs in the kernel.
- Post-hoc Hermitian symmetrisation of `W^(1)`.
- Labelling the azimuthal average as "true partial-wave projection".
