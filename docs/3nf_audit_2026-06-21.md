# 3NF Implementation Audit — 2026-06-21

This document is the **strict, evidence-based audit** of the chiral N²LO
three-nucleon force (3NF) implementation in `Tic-tac`. It is the *input* to
the phased fix plan in
[`docs/superpowers/plans/2026-06-21-3nf-audit-and-fix.md`](superpowers/plans/2026-06-21-3nf-audit-and-fix.md).
Every claim below is backed by a specific file:line reference and (where
relevant) a literature formula. The current code was *not* assumed correct;
each piece was re-derived from the conventions in Epelbaum 2002 (E2002),
Golak 2010 (G2010), Hebeler 2015 (H2015), and Witała 2008 (W2008).

## Locked physics conventions

1. **Spectator-1 picture**. `W^(1)` has particle 1 as spectator, pair = (2,3). Jacobi momenta: `p` = pair relative, `q` = spectator.
2. **Momentum transfers**. `Δp = p' − p`, `Δq = q' − q`; `q_1 = Δq`, `q_2 = Δp + Δq/2`, `q_3 = Δp − Δq/2`.
3. **AGS kernel operator ordering**. Per W2008 eq. (3) and G2010 §2: `K_AGS = P·V + W^(1)·(1+P)`, i.e. `W^(1)` on the **left**, `(1+P)` on the **right**, with `P = P₁₂₃ + P₁₃₂`. The equality `W^(1)(1+P) = (1+P)W^(1)` *only* holds for fully antisymmetric matrix elements; in the kernel where the ket is a single Faddeev component, the two forms are physically different operators.
4. **c_E contact (E2002 eq. 2.10 + A-4)**: `V^(1)_cont = −½ E Σ_{j≠k∈pair} (τ_j·τ_k) = −E·(τ₂·τ₃)`, `E = c_E/(f_π⁴ Λ_χ)`. **Pure spin-scalar**, only `τ₂·τ₃`. Selection rules: `L_2N=L_2N'=0`, `l_1N=l_1N'=0`, `j_1N=½`, `J_2N=S_2N`, `T_2N'=T_2N`, `S_2N'=S_2N`.
5. **2PE c_1/c_3 rank-0 (G2010 eq. 18)**: `(σ₂·q₂)(σ₃·q₃) → ⅓(σ₂·σ₃)(q₂·q₃)`. Here `σ₂·σ₃` IS the pair eigenvalue `2S(S+1)−3`.
6. **c_4 (E2002 eq. 2.2-2.3)**: carries `τ₁·(τ₂×τ₃)`, imaginary for `T_3N=½` doublet, opens off-diagonal T_2N transitions. **Not implemented** in current code.
7. **Regulator (E2002 eq. 3.19)**: `f_R(p,q;Λ) = exp(−((4p²+3q²)/(4Λ²))²)` — squared-Gaussian.
8. **Units**. p, q, m_π, f_π, Λ_χ, Λ in fm⁻¹; c_D, c_E dimensionless; c_1, c_3, c_4 in fm (from GeV⁻¹ × ħc/1000).

## Confirmed bugs (each verified against the locked conventions)

### B1 — `c_E` contact erroneously depends on pair-spin eigenvalue (**critical**)

**Location.** `src/utils/chiral_3nf_recoupling.cpp:18-63` (`recoupling_3nf_scalar`); used by `src/interactions/chiral_N2LO_3NF.h:144` in `W1_contact` (the c_E term).

**Bug.** The helper returns `sigma_sigma * tau_tau = (2S(S+1)−3)(2T(T+1)−3)`. The c_E contact per E2002 eq. (2.10)/(A-4) is **pure spin-scalar** — only `τ₂·τ₃`. So when `S_2N=0` (singlet pair), the c_E term gets an erroneous factor of `σ₂·σ₃ = −3`; when `S_2N=1` (triplet), it gets `+1`. The c_E must be identical in singlet and triplet pairs (for the same `T_2N`).

**Evidence.**
- `formula_reference.md:142-143` (own doc): "Operator-wise: **spin-scalar** (no σ), isospin = `τ_2 · τ_3`".
- `formula_reference.md:188-196` (own doc, A_cE closed form): only `δ_{S_2N S_2N'}` and `δ_{T_2N T_2N'}`, **no** `2S(S+1)−3` factor.
- E2002 eq. (2.10): `V^(1)_cont = −½ E Σ(τ_j·τ_k)` — no σ operator.
- H2015 eq. (13) with c_E term: spin trace is trivial (`S_2N` conserved, no operator).

**Numerical impact.** For the dominant 3S1 channel (`S_2N=1`, `T_2N=0`) the wrong helper returns `(+1)·(−3) = −3`; the correct c_E value is `τ₂·τ₃ = −3`. By **luck** the result matches for this single channel. But for the 1S0 (`S=0, T=1`) the wrong helper returns `(−3)·(+1) = −3` while the correct c_E value is `+1`. The sign is **flipped** in singlet-pair channels. In any channel where pair spin changes between bra and ket (forbidden for c_E), the wrong helper returns 0 correctly, but for any singlet-pair channel the magnitude is also wrong by a factor of 3.

**Fix.** Phase 2 — add `recoupling_3nf_contact_cE` returning the **pure τ₂·τ₃** matrix element (`δ_{T T'} · (-1)^{T+1} · (2T(T+1)−3) · {½½T; ½½T_3N}_6j`), and restrict `recoupling_3nf_scalar` (renamed to `recoupling_3nf_2pe_scalar`) to the 2PE c_1/c_3 rank-0 piece where `σ·σ × τ·τ` is correct.

### B2 — `c_4` 2PE cross-product term is silently dropped (**critical**)

**Location.** `src/interactions/chiral_N2LO_3NF.h:49` (`m_c4` declaration), `:110` (storage comment), `:60` (`enabled()` checks c4), `:94-97` (`W1_element` body — no `W1_2pe_c4` call). Also `src/interactions/three_nucleon_force_model.cpp:29-39` — the factory passes `c4_idaho_n3lo = +5.4` GeV⁻¹ from `constants.h`, so production runs of `chiral_N2LO` with Idaho N3LO 2NF always have non-zero `c_4`.

**Bug.** The class advertises itself as `chiral_N2LO` (the full N²LO 3NF), accepts a `c4` parameter, has an `enabled()` that includes c4, but `W1_element` (lines 83-98) only calls `W1_contact`, `W1_1pe_contact`, `W1_2pe`. The c_4 term — `(g_A/2f_π)²·τ₁·(τ₂×τ₃)·(σ₂·q₂)×(σ₃·q₃)·(cross product)` — is **never evaluated**.

**Evidence.**
- Class comment at `chiral_N2LO_3NF.h:13-26` claims "Three contributions at this order: 1. 2PE proportional to c_1, c_3, c_4". But only c_1 and c_3 are implemented.
- Constructor initialiser list comment `:49`: `m_c4(c4 * hbarc / 1000.0) // c_4 LEC: GeV⁻¹ → fm — reserved for tensor part`. "Reserved" = not implemented.
- `grep -n 'm_c4' src/interactions/chiral_N2LO_3NF.h` shows only declaration and `enabled()` — no actual usage.
- E2002 eq. (2.2)-(2.3): the 2PE term has three LEC combinations (`c_1`, `c_3`, `c_4`); all three are needed for the full N²LO 3NF.

**Fix.** Phase 5 — since a *correct* c_4 PWD requires implementing the `τ₁·(τ₂×τ₃)` spin-isospin recoupling and the `(σ₂×σ₃)·(q₂×q₃)` momentum cross-product in 5D (non-trivial), we will **explicitly hard-block** non-zero `c_4`:
- Constructor prints a one-time strong warning to stderr.
- `name()` returns `"chiral_N2LO_without_c4"` when `c_4 ≠ 0`.
- New `bool c4_implemented() const` returns `false`.
- The metadata output records `c4_implemented=false`.
- Document the deferred implementation (formula sketch + selection rules + test design) so a future PR can complete it.

A rough/empirical c_4 will *not* be added to satisfy the letter of N²LO.

### B3 — Shared `recoupling_3nf_scalar` helper for two physically different operators (high)

**Location.** `src/utils/chiral_3nf_recoupling.h:50` (declaration), used in `chiral_N2LO_3NF.h:144` (c_E contact) and `:306` (2PE c_1/c_3 rank-0).

**Bug.** The c_E contact requires `τ₂·τ₃` only; the 2PE rank-0 requires `(σ₂·σ₃)(τ₂·τ₃)`. They cannot share a helper.

**Fix.** Phase 2 — split into `recoupling_3nf_contact_cE` (τ₂·τ₃ only) and `recoupling_3nf_2pe_scalar` (σ·σ × τ·τ). The existing body of `recoupling_3nf_scalar` is correct *for 2PE rank-0* and will be retained under the new name.

### B4 — Inconsistent `W^(1)` operator ordering between header and solver (high)

**Location.** `src/interactions/three_nucleon_force_model.h:42-43` (header says `W = (1+P+P²)·W^(1)` — LEFT form); `src/core/faddeev_solver/solve_faddeev.cpp:252-258` (solver implements `W^(1)·(1+P)` — RIGHT form, correct per W2008).

**Bug.** The header's `(1+P+P²)·W^(1)` describes the full physical 3NF on the *antisymmetrised* 3N Hilbert space; the solver's `W^(1)·(1+P)` describes the AGS *kernel* acting in spectator-1 Faddeev space. These are different objects and the comments conflate them. No assumption `[W^(1), P] = 0` may be made in the kernel.

**Evidence.**
- W2008 eq. (3): the AGS driving term and kernel both contain `W^(1)·(1+P)` (left `W^(1)`, right `(1+P)`).
- G2010 §2: same convention.
- `solve_faddeev.cpp:252` correctly implements `W^(1)·C + W^(1)·P·C` (Born) and the same combination drives every Neumann iteration.

**Fix.** Phase 4 — header comments and treatise rewritten to use the solver's convention unambiguously. A dense operator-ordering test will explicitly verify that the kernel computes `P·V·C + W^(1)·(1+P)·C` and *not* the left-symmetrised form.

### B5 — W1 cache key omits `c_1, c_3, c_4` and the momentum grid (high)

**Location.** `src/interactions/w1_pw_cache.cpp:138-165` (W1Key struct).

**Bug.** The cache key includes `c_D, c_E, Lambda_3NF, Np_WP, Nq_WP, J_2N_max, two_J_3N_max, ...` but omits `c_1, c_3, c_4` (which all affect `W^(1)` via the 2PE kernel) and the actual `p_WP_array`/`q_WP_array` values. Two production runs that differ only in their 2NF (e.g., `N2LOopt` with `c_1 = −0.86` vs `Idaho_N3LO` with `c_1 = −0.81`) but share `c_D, c_E, Λ_3NF` would **silently reuse** the cached W^(1).

**Evidence.** `grep -n 'k.c1\|k.c3\|k.c4' src/io/cache_layer/` — no hits. The W1Key fields in `cache_keys.h` simply do not exist for c_1/c_3/c_4.

**Fix.** Phase 6 — extend W1Key with `c1, c3, c4, p_grid_hash, q_grid_hash, physics_schema_version`; bump `W1_SCHEMA_VERSION`; old caches invalidated.

### B6 — W1 cache stores `float` (medium)

**Location.** `src/interactions/w1_pw_cache.h:57` (`std::vector<float> m_data;`), `:54` (`total_bytes` returns `sizeof(float)`), `w1_pw_cache.cpp:230` (assignment to `float`), `w1_pw_cache.h:46` (cast back to `double` on read).

**Bug.** 3NF has strong cancellations between c_E, c_D, c_1, c_3 contributions. `float` has ~7 decimal digits; for typical 3NF matrix elements that cancel to ~1e-2 from individual pieces of ~1e+2, `float` storage loses ~5 digits of precision, contributing a `~1e-5` relative noise floor that compounds under Padé.

**Fix.** Phase 6 — change to `std::vector<double>`. Provide an optional `float` compression mode behind a flag for memory-constrained runs, with a documented precision/coverage table.

### B7 — Documentation mislabels azimuthal average as "true partial-wave projection" (medium)

**Location.** `src/interactions/chiral_N2LO_3NF.h:73-77, 168-184, 254-282`, and treatise `16_3nf_pw_projection.tex`.

**Bug.** The 2PE kernel `kernel_2pe_c1c3` (kernels header lines 202-229) explicitly drops `Δp·Δq` cross terms under the `φ_{p'}` azimuthal average. This is exact for the c_E contact (diagonal in everything) but is an **approximation** for c_D, c_1, c_3 — the full Golak 2010 reduction is a 5-dimensional angular integral that does not factorise to `∫dx` until *after* the LS-coupling recoupling. The code calls this a "true partial-wave projection".

**Evidence.**
- `chiral_3nf_pw_kernels.h:30-39` (own comment): "cross-terms `Δp·Δq` drop out at the scalar (rank-0) level" — admits approximation for rank-0.
- `formula_reference.md:54-58`: "For a generic 3NF piece one may need up to 5 integrations ... but with monopole pion propagators or after [H2015] factorisation the result reduces to a single `∫dx`." This reduction is not done — current code does monopole only.
- G2010 §3 and H2015 §2: the full PWD requires the 5D integral; factorising to 1D requires non-trivial recoupling work.

**Fix.** Phase 10 — documentation rewritten to say "azimuthally-averaged partial-wave projection (exact for c_E; rank-0 monopole approximation for c_D, c_1, c_3; rank-2 piece from `Y_2(q̂)` only)". Code comments updated. A *reference backend* doing the full 5D integral on a small grid will be added as a separate benchmark, not as the production path.

### B8 — Rank-2 2PE Hermitian symmetrisation is a band-aid (low)

**Location.** `src/interactions/chiral_N2LO_3NF.h:339-393`.

**Observation.** The 2PE rank-2 contribution is symmetrised by averaging two evaluations (`(recoup2·integ2 + recoup2_T·integ2_T)/2`) because the spatial kernel `kernel_2pe_c1c3_rank2` carries `pp² = p_c²` (ket-only) and is therefore not manifestly Hermitian. The band-aid works numerically (Hermiticity test passes) but obscures the algebra.

**Fix.** Out of scope for this audit (would require deriving the manifestly Hermitian kernel from the 5D integral — see B7). Documented as open issue in final report.
